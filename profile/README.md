<p>把「真实住宅 IP」当成一个开关是常见的误解。它其实是一组参数共同决定的：出口归属、地址段独占程度、容器指纹、时区语言、会话保活策略。每个参数都有自己的取值范围和副作用，改错一个，整体表现就会走形。这篇按说明书的方式逐项列，给出参数名、常见取值、推荐值和影响面，方便照着配。推荐值来源于一般实践，仅供参考。</p>
<h2>一、这份说明书覆盖的三层参数</h2>
<p>参数按层分：出口层决定「平台看到你从哪里来」，环境层决定「平台看到你是谁」，会话层决定「这段连接能维持多久」。三层缺一层，前两层做得再好也会漏。</p>
<h3>为什么必须分层看</h3>
<p>因为三层的故障表现完全不同。出口层出问题，表现是登录时就要确认；环境层出问题，表现是登录能过但操作中频繁被要求重来；会话层出问题，表现是对话中途断开。按表现就能反推是哪一层，比逐个试参数快得多。</p>
<h3>单号独享的边界在哪</h3>
<p>「单号独享一段网络」指的是这个号独占一条出口及其对应的地址段，不与其它号共享。它保证的是一号出问题不牵连别的号，不保证这个号本身永远不出问题。这个边界要说清楚，否则期望会落空。</p>
<h2>二、出口层参数</h2>
<p>出口层有四个关键参数，前两个决定「像不像住宅」，后两个决定「稳不稳」。</p>

<p>四项里最容易被忽略的是「地址段独占度」。很多人只问类型不问独占，拿到的是双 ISP 大池里的一个地址，表面上是住宅，实际上同段有几十个用户在跑。表现就是时好时坏，且好坏跟自己的操作无关。</p>
<h3>原生家宽与双 ISP 的取舍</h3>
<p>原生家宽的优势是归属信息最自然，长期固定使用最稳；劣势是供给有限，扩容需要等。双 ISP 的优势是供给稳定、批量开号方便；劣势是归属记录相对「工业化」，长期高频使用需要注意节奏。合理做法是主力号用原生，一般号用双 ISP。</p>
<h3>延迟与丢包怎么测</h3>
<p>建议连测三天，每天三个时段（早、午、晚各一次），每次二十个包。看的是抖动和长尾，而不是平均值。平均值好看但偶尔丢一批包，比平均稍差但一直平稳要危险得多。</p>
<h2>三、环境层参数</h2>
<p>环境层参数决定「这个号在平台上长什么样」。这一层的原则是一号一套，不共用任何一项。</p>

<p>分辨率这一项很多人觉得无所谓，其实它是同批号之间「像不像同一批机器」的信号。同批次的号，分辨率、字体列表、屏幕色深应该保持一致的档位；不同批次之间才需要有差异。</p>
<h3>时区错位的容忍度</h3>
<p>出口在洛杉矶，时区设成上海，差十五小时，属于明显错位。实践中容忍度大约在两小时以内，超出这个范围就容易被计入不一致项。跨国运营时，建议直接按出口城市设置，不做任何「统一时区」的简化。</p>

<h2>四、会话层参数</h2>
<p>会话层管的是连接的持续性与重连策略，参数不多但影响体感最大。</p>
<h3>保活间隔</h3>
<p>长连接需要有节奏的保活，间隔太短会产生大量无用请求，太长又容易被中间设备回收。常见做法是六十到九十秒一次轻量探测，具体以线路商建议为准。</p>
<h3>重连策略</h3>
<p>重连要区分两种情况：链路抖动导致断开，重连即可；出口 IP 发生变化导致会话失效，重连也没用，必须重新登录。建议在客户端做判断，IP 未变就静默重连，IP 变了就提示人工介入，避免无意义的重试把异常放大。</p>
<h2>五、参数组合的几条禁忌</h2>
<p>参数单独看都对，组合起来互相打架的情况很常见，下面几条是踩过坑之后总结的。</p>
<p>第一条，独享出口配共用容器。出口是一号一条，容器却共用，等于给每个号换了门牌号却让他们长同一张脸，白花钱。</p>
<p>第二条，同一出口配多个时区。一条线在两个容器里被设成两个时区，同时在线时就是一个明显的矛盾信号。</p>
<p>第三条，短保活配低质量线路。保活频率高但线路抖动大，会产生大量半开连接，反而拖慢整体响应。</p>
<p>第四条，频繁换出口配长期账号。老号突然换城市，变动越大越显眼。要迁移就一次迁到位然后不动，不要反复横跳。</p>
<h2>常见问答</h2>
<h3>参数都按推荐值配了就一定稳吗？</h3>
<p>答：不一定。推荐值是降低常见问题的概率，不是消除所有问题。平台的判定是多维的，操作节奏、内容特征、使用时段都会参与，参数只是其中一层。把参数配好是基础，不是终点。</p>
<h3>一条原生家宽能带几个号？</h3>
<p>答：技术上能带多个，但不建议。原生家宽的价值就在于「一段网络对应一户人家」，带多个号等于放弃这个价值。若必须复用，建议限制在同一批、同一用途、不同时段使用。</p>
<h3>双 ISP 出口的归属信息怎么看是否正常？</h3>
<p>答：查两项：ASN 是否属于住宅宽带运营商，注册地址与实际出口城市是否吻合。两项都对上，归属信息就算合格。不需要追求「每个字段都完美」，那既不现实也没必要。</p>
<h3>参数改了之后要观察多久才能下结论？</h3>
<p>答：至少三天，且要覆盖不同时段。只看一天很容易被当天的线路波动误导。观察期内尽量保持其它参数不变，否则改了三个参数再看结果，等于什么都没测出来。</p>
<h2>合规提示</h2>
<p>本文列出的参数与推荐值用于自有账号的正常网络配置，不构成规避平台规则的建议。所有线路应通过合规渠道获取，用途需符合服务商条款与当地法律。</p>
<p>参数文件中可能包含账号标识、出口地址等敏感信息，建议加密存放并限制访问范围，不要随代码仓库公开提交。</p>
